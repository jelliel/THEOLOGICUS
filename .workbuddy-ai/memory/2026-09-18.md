## v66 — verrouillage au lancement : « se souvenir de moi » + robustesse

Demande : « j'ai le splash screen avec un mot de passe admin et des questions
quiz au lancement… rendre cela plus robuste et rapide, et surtout une option

- validite **7 jours**
- penalites **adoucies** (chrono 20 s, malus leger, mais plus de touche au

### Ce qui a ete fait

**Mot de passe** : plus en clair. `AUTH_HASH` = SHA-256 sale
(`sha256hex('theologicus-v66:' + mdp)`), verifie par une implementation
**pur JS** (pas `crypto.subtle` : il exige un contexte securise, et un WebView
servi en `file://` ne l'est pas). Validee contre les vecteurs NIST (`abc`,
chaine vide, 448 bits) + l'empreinte du mot de passe + un cas UTF-8 avec emoji
compare a Python. ⚠️ Ne pas ecrire le mot de passe dans un commentaire : c'est
le piege dans lequel je suis tombe au premier essai, verifie par
`grep -c joerabill39` sur `mobile/www/index.html` (doit valoir 0).

**Memorisation** : `localStorage['theologicus_remember']` =
`{v:1, mode:'admin', exp, tok}` ou `tok = sha256hex('remember:' + AUTH_HASH)`.
Lecture = verification `exp` **et** `tok`. Revocation : bouton
`#forget-remember-btn` dans ⚙ PARAMÈTRES > 🔐 ACCÈS AU LANCEMENT, plus
`window.theologicusForgetRemember()`.

**Anti-clignotement** : un `<script>` inline juste apres `#auth-overlay` le
masque **avant le premier rendu** si l'enregistrement est valide. Le module
principal re-valide et remet `display=''` sinon.

**Adoucissement** : chrono 15 → 20 s ; plus de liste noire `failedQuizIds` ;
`difficultyLevel` monte avec les BONNES reponses (plafond 3, plus de palier
« expert ») ; `blur`/`visibilitychange` mettent le chrono **en pause** au lieu
de remplacer la question et de decrementer.

**Robustesse** :
- melange **Fisher-Yates** (remplace `sort(() => Math.random() - 0.5)`, biaise)
- `data-opt` + delegation sur `.auth-box` (le texte de l'option etait injecte
  dans un `onclick` entre apostrophes → une apostrophe cassait le bouton)
- `initWatermark` / `initDevtoolsProtection` idempotents
- garde-fou `pickQuestion()` : ne renvoie jamais `undefined`
- `busy` pour bloquer le double-clic pendant les 1200 ms de retour

### v67 — retrait de widgets UI

L'utilisateur a montre une capture avec deux elements cercles en rouge et a
demande de les supprimer :
1. **Widget vertical a droite** (`#floating-sidebar`) — bar qui apparait au
   survol d'un message assistant avec 6 boutons (copier, lire, memoire,
   nouveau, exporter, Hermes)
2. **Bouton circulaire en bas a droite** (`#memory-toggle`) — ouvre le
   panneau memoire (par ailleurs joignable depuis le rail)

Approche : `display: none !important;` dans la regle CSS de base de chaque
element. Le DOM et tous les gestionnaires clavier restent en place, donc rien
ne casse si l'utilisateur change d'avis (une seule ligne a supprimer pour
revenir en arriere).

Verifie via CDP (`getComputedStyle` -> `display: none` sur les deux) + capture
d'ecran. APK locale 18 s, commit `91edeb4`, CI run #35360438491 → success,
release `apk-v1.0.45` (11 344 825 o), `93d832…`.

Note : `sessionStorage.setItem(...)` via CDP **avant** `Page.navigate` ne
persiste pas — l'origin `about:blank` est opaque. Pour mettre la session en
place avant d'ouvrir l'app, faire `navigate → setItem → reload`.

## Proposition 2.0 (aucun code modifie)

Question de Fatih : « si cela dependait de toi pour mettre l'appli en version
2.0, quelles options, fonctionnalites, ameliorations d'interface et surtout
extras concernant la theologie ». Demande **consultative** → livrable ecrit,
pas de patch.

Inventaire fait avant de repondre, pour ne pas proposer ce qui existe deja.

**Le constat qui structure tout** : `buildSystemPrompt()` (l. 13742) ne donne
au modele que des **regles** de citation (formats, liste d'abreviations
interdites, style des blocs `schema`, section « Questions de suivi »
obligatoire), jamais de **contenu**. Il est reconstruit a chaque appel
(l. 13742, 14522, 14606, 14695, 15205, 15256, 15330) et il n'existe **aucune**
fonction de recuperation documentaire. Les **51 Mo** de corpus locaux
(`bible/` 4,3 · `quran/` 2,6 · `tafsir/` 41 · `libs/` 3,1) ne servent donc
qu'a l'affichage : le tafsir n'est charge que par
`window.__ensureTafsirSurah(p)` au survol. L'IA ne les voit jamais.

Formes des tranches, pour memoire : `bible/b1.js` →
`window.__bibleBooks[1] = {"1":{"1":"texte",…}}` ; `quran/q1.js` →
`window.__quranSurahs[1] = {nomPhon, versets:{"1":{text, arabe}}}` (l'arabe est
donc deja la). `tafsir/index.js` → `window.__tafsirIndex`.

Absences **verifiees** par recherche : recherche plein texte 0 (aucune fonction
`searchBible`/`searchCorpus`, aucun `id="search*"`), concordance 0, lexique /
Strong 0 (les 38 « strong » sont des balises `<strong>`), catena 0, synopse 0,
versification 0, calendrier 0, embeddings 0, SQLite 0 (mais `indexedDB` 17
usages), `navigator.onLine` jamais appele. Denzinger : 1 mention, 0 donnee.
`libs/` contient deja fonts, html2canvas, jspdf, jszip, mammoth, pdf.js.

La « bibliotheque de reference » declare 41 sources (`cat:` ×41) mais chacune
est un simple `url:` vers `vatican.va` → **decorative hors ligne**. C'est une
liste de liens, pas un corpus.

Livrable : `.workbuddy-ai/artifacts/v2.0-proposition.md`, structure en trois
paliers.

1. **Verifier** — index inverse local + recherche globale ; **verificateur de
   citations** (extraire les references, controler leur existence, comparer le
   texte cite au corpus local, annoter) ; renvois cliquables. Idee centrale :
   transformer une *promesse* du prompt en *garantie* du logiciel, 100 % hors
   ligne, sans modele ni telechargement.
2. **Retrouver** — versification Vulgate / hebraique / Septante, concordance de
   racines, index thematique, glossaire theologique, calendrier liturgique
   (algorithmique, zero donnee), dossier d'etude PDF.
3. **Etudier** — synopse des Evangiles, comparateur de traductions (Crampon
   1923 + Vulgate, domaine public), conciles et magistere en local, catena
   patristique, apparat critique allege, biometrie.

Refus argumentes : embeddings / RAG neuronal (un index BM25 local fait mieux sur
ce corpus), Strong complet, catena auto-generee par le modele, telechargement
des URL vatican.va, synchronisation cloud, compression des 51 Mo.

Un schema a ete produit (couche de verification) et `overview.md` complete.
