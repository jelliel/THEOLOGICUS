# 2026-09-12 — THEOLOGICUS.html — v37 : translittération phonétique au survol

## Demande (Fatih)
Tooltip au survol d'un mot en langue étrangère (grec, latin, hébreu, arabe, autres)
qui donne la **translittération phonétique**.

## Livré : patch v37 (additif, idempotent)
- `UI_PROPOSAL/apply_v37.py` → `<style id="v37-translit-css">` + `<script id="v37-translit-js">`
  avant le dernier `</body>`.
- Élément `#v37-tip` (z-index 129999, `pointer-events:none`, opacity 0→1, fond
  `rgba(7,11,18,.96)` + variantes par thème dont `v6-light` en blanc).
  3 lignes : langue • mot original (`dir="auto"`) • translittération en gras.
- Détection du mot : `document.caretRangeFromPoint` → extension aux limites de mot
  avec `[\p{L}\p{M}]`, throttle 70 ms, cache des résultats.
- Surbrillance du mot via **CSS Custom Highlight API** (`CSS.highlights.set('v37-word', …)`),
  non destructrice (aucune mutation du DOM). `::highlight(v37-word)` en CSS.
- Interrupteur `◈ TRANSLITTÉRATION : ON/OFF` ajouté dans `#v6-more-menu` (section
  « Lecture »), persistance `localStorage['v37-translit']`, raccourci **Ctrl+Alt+T**.
- API de test : `window.__V37` (translit, scriptOf, wordAt, setEnabled, el, lastKey).

## Moteur (9 alphabets)

arabe (harakat, chadda, alif khanjari, **assimilation de l'article devant lettre solaire**),

copte, arménien, géorgien.

## Pièges rencontrés (à retenir)
1. **Le canal d'édition décode les `\uXXXX` et normalise les diacritiques combinants** →
   impossible d'écrire `'\u05bc'` via Write/Edit. Contournement : construire les
   caractères spéciaux avec `String.fromCharCode(0x05BC)` dans le JS, et écrire les
   plages via un script Python (`fix_v37_escapes.py`) qui réécrit en `\uXXXX`.
2. Un `\uXXXX` littéral dans le **docstring** d'un .py → `SyntaxError: unicodeescape`.
3. Ordre `scriptOf` : **copte AVANT grec** (le bloc copte 2C80–2CFF + 03E2–03EF, sinon
   le grec capte tout), et syriaque (0700–074F) après arabe (0600–06FF) — sans conflit.
4. `isHar()` incluait 0x0651 (chadda) → la recherche de chadda sautait la chadda elle-même.
   Il faut deux prédicats : `isVp()` (voyelles, exclusion chadda) et `isHar()`.
5. Ordre réel des diacritiques : **base, voyelle, dagesh** (ex. בְּ = 05D1 05B0 05BC)
   → détection du dagesh sur i+1 **et** i+2.
6. `waw`+holam / `yod`+hiriq : émettre la voyelle **et faire `i++`** sinon la voyelle
   est comptée deux fois (« shaloom »).
7. Mes échantillons de test saisis à la main perdaient leurs diacritiques (Allāh saisi
   sans chadda) → **toujours tester les mots construits par codepoints** (`U+XXXX`).
8. Bloc de test injecté sans `z-index` → `caretRangeFromPoint` touchait un élément
   superposé, faux négatif. Toujours `z-index` élevé + vérifier `elementFromPoint`.
