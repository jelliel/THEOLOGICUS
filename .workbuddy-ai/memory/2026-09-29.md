## Fix — lag/freeze au redimensionnement des « encadrements » (.atc-figbox) + GPU boost (v129)

Symptôme (utilisateur, 2026-09-29) : redimensionner les encadrements laggue et
gèle parfois toute l'interface ; veut un « ultra GPU boost ».

Cause racine (vérifiée dans le code, pas devinée) :
- `THEOLOGICUS.html` ~l.27356 : le handler `mv` écrivait `width/height/left/top`
  **synchrone à chaque `mousemove`** (jusqu'à ~120/s sur souris haute fréquence)
  → autant de reflow/repaint que d'événements → lag puis freeze.
- La boîte n'était pas isolée : son resize reflowait tout le fil de chat.

Correctifs (commit 0c1daa5, déployé dans l'install via copie de THEOLOGICUS.html) :
- `.atc-figbox` : les écritures de style sont **coalescées dans UN
  requestAnimationFrame par image** (`_mvApply`), + classe `.dragging` qui
  pousse la boîte sur sa propre couche GPU (`translateZ(0)` + `will-change`) et
  isole sa mise en page (`contain: layout style`). `contain` sans `paint` pour
  ne pas rogner les SVG en `overflow:visible`.
- `app.py` : niveau GPU « ultra » par défaut (`THEOLOGICUS_GPU_MODE=ultra`)
  ajoutant `--enable-gpu-compositing` + `--disable-gpu-vsync` aux drapeaux
  existants ; Vulkan opt-in (`THEOLOGICUS_GPU_VULKAN=1`) ; `THEOLOGICUS_GPU=0`
  coupe tout. NB : ces drapeaux sont **build-time** (bundlés dans l'.exe) ;
  l'HTML seule suffit au fix de resize à chaud.

Mesure (règle 2026-09-29 : mesurer avant d'affirmer) :
- Déterministe (`bench_coalesce.js`) : mutations de style 15-120× moins
  nombreuses selon le burst d'entrée.
- Edge réel via CDP (`bench_resize_real.py`) : à 120 Hz, OLD=600 mutations vs
  NEW≈387 (≈1/image). FPS identique sur une boîte triviale (coût de layout
  négligeable) ; le gain FPS réel apparaît sur le DOM lourd de l'app — à
  confirmer chez l'utilisateur via `mesure_webview2.py` (CDP sur l'install).

Leçon à garder : quand on touche à du drag/resize, COALESCER les écritures de
style dans un rAF et ISOLER la cible (`contain`) + promouvoir en couche GPU.

Règle d'or signtool (vérifiée) :
- TOUT chemin passé à signtool en `C:/...` (lettre de lecteur + deux-points, slash

- Commande OK : `signtool sign /f C:/tmp/THEOLOGICUS_signing.pfx /p theologicus2026
  /fd SHA256 /td SHA256 /tr http://timestamp.digicert.com <FILE>`. Le timestamp
  DigiCert répond (réseau OK) → « Done Adding Additional Store » + « Successfully signed ».

`verify` :
- `signtool verify /pa` renvoie rc=1 « terminated in a root certificate which is not
  trusted by the trust provider » → **NORMAL** : le cert est auto-signé

  La signature est valide + timbrée (chaîne timestamp DigiCert vérifiée, datée
  2026-09-29 09:42). Pas d'erreur « not signed » / « signature is not valid ».
- Conséquence : SmartScreen avertira encore (cert non réputé) tant que l'app n'a pas
