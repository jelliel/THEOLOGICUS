# 2026-10-20 — v617 : le transport APK ne peut plus pendre, et il se raconte

## Plainte : « la version APK a toujours des soucis de HTTP »
Tous les modèles. Aucun code HTTP obtenu de l'utilisateur (la question posée
n'a pas été répondue) -> on ne théorise pas : on **rend la panne observable**
et on corrige les deux trous STRUCTURELS trouvés dans le code.

## Ce qui manquait vraiment (mesuré dans le code, pas supposé)
1. **Aucun délai sur le chemin direct.** `theoFetchReseau` appelait `_direct`
   sans `AbortController` : un réseau mobile qui ne coupe pas la connexion,
   ou un edge qui ne répond jamais -> l'interface tournait sans fin. C'est le
   « souci HTTP » sans message ni issue.
2. **Repli natif déclenché seulement sur 403 ou échec réseau.** Un 502 / 520 /
   522 / 524 (edge Cloudflare) ou un 408 mourait alors qu'un autre chemin
   réseau pouvait aboutir.
3. Aucun moyen pour l'utilisateur de rapporter le CORPS exact du fournisseur —
   chaque itération précédente (v603/v610/v611b/v613) a coûté des allers-retours
   faute de cette pièce.

## Correctifs (v617)
- Délai sur les **EN-TÊTES**, levé dès la réponse (une génération en streaming
  n'est jamais coupée) : **45 s** si `stream:true`, **180 s** sinon (une réponse
  non streamée n'envoie ses en-têtes qu'avec le corps), `__theoDelaiMs` pour les
  bancs. Appliqué **même sans pont natif** : mieux vaut une erreur claire.
- Repli natif élargi à **408 / 425 / 5xx** ; **jamais** 401/402/422 (verdicts du
  fournisseur : rejouer ne les change pas et une génération rejouée coûte des
  jetons). 429 non plus (rejouer aggrave la limite).
- Abandon VOLONTAIRE de l'appelant (son `signal`) -> aucun rejeu, erreur intacte.
- Journal borné (12 événements) + `window.__theoDiagReseau()` : version,
  plateforme, ponts, endpoint réel, modèle, statut, **corps exact**, tentatives.
  `throwApiError` y écrit AUSSI les erreurs non rejouées. **Aucune clé.**
- Bouton **🧪 DIAGNOSTIC** dans la modale de clé -> panneau copiable.
- Messages dédiés 408/429/5xx nommant le transport + renvoi au diagnostic.

## Pièges vérifiés sur pièce
- 🔴 **`.modal-overlay` est en `display:none`** : un panneau créé avec cette
  classe SANS `active` existe dans le DOM mais reste INVISIBLE. Le banc
  « le panneau s'ouvre » passait (existence) ; c'est la **capture d'écran** qui
  l'a révélé. Assertion corrigée : `display` + surface réelle.
- 🔴 **`#auth-overlay` porte `display:flex !important`** : `style.display='none'`
  ne le masque pas (il faut la classe `hidden` ou `!important`). Utile pour
  toute capture d'écran de l'app.
- 🔴 Emoji dans une ancre de script Python : `grep -c` avec `🔴 ` renvoie 0 alors
  que `grep -n` trouve la ligne (variante de sélection). Ancrer sur le TEXTE.
- 🔴 `err.model = model || '';` existe **deux fois** dans le fichier : ancre
  longue obligatoire (`apiMessage` + `model`).
- 🔴 Toujours pas de backticks dans `python -c` / `node -e` : bash les exécute
  (`.modal-overlay: command not found`). Écrire un FICHIER.

# v618 — ANNOTER UN ENCADRÉ (commentaire + surlignage)

## Plainte
« Lorsque je fais un encadrement d'une phrase ou d'un mot, je n'arrive pas à
faire de commentaire pour ce mot encadré : je veux l'option — commentaire,
surlignage ou autre. »

## Cause RÉELLE (lue dans le code, pas supposée)
`.atc-figbox` est une **SURCOUCHE** (`position:absolute`, `z-index:6`,
`background:transparent`, `user-select:none`) posée sur le texte : elle capte
le `mousedown` pour le déplacement et **empêche de sélectionner ce qu'elle
entoure**. Il n'existait AUCUN chemin d'annotation pour un texte encadré ;
la seule issue était de supprimer le cadre. Ce n'était donc pas un réglage
manquant, mais une impasse d'interaction.

## Livré
- Barre d'outils du cadre : **💬** (commentaire) et **🖍** (surlignage), à côté
  des outils existants (couleur, épaisseur, remplissage, rotation, ⧉, 🗑).
- 💬 : panneau de note (citation du texte ancré, `Ctrl+Entrée`, `Échap`,
  Supprimer) ; la note vit dans `f.note` **du cadre** (pas dans une annotation
  séparée : rien à ré-ancrer) et part dans les DEUX exports (MD + riche).
- Badge **💬 toujours visible** sur un cadre annoté — le survol n'existe pas au
  doigt ; il rouvre la note et **ne déplace pas** le cadre.
- 🖍 : surligne **exactement** le texte ancré (offsets v609), couleur déduite du
  cadre (5 teintes de marque), second clic = retrait ; refus explicite si le
  cadre n'a pas d'ancre (cadre dessiné à la main).
- Badge 24 px sur `pointer:coarse` (doigt), 18 px à la souris.

## Défaut trouvé EN ÉCRIVANT LE BANC
🔴 Un **simple clic** sur un cadre (`mousedown`+`mouseup` sans déplacement)
appelait `persistFig` → `delete f.ancre`. Le correctif **v609** (le cadre suit
son texte au redémarrage) était donc **annulé par un appui**, silencieusement.
`persistFig` ne retire plus l'ancre que si la géométrie a réellement changé.
C'est ce qui a fait échouer 5 assertions du banc : le 🖍 refusait « sans ancre ».

## Pièges de banc (vérifiés)
- 🔴 **Mesurer un `getBoundingClientRect` dans le MÊME `evaluate` que le rendu**
  donne une position périmée : le clic Playwright tombe à côté (faux négatif
  « la barre d'outils ne s'ouvre pas »). Relire le rect APRÈS stabilisation.
- 🔴 `renderMessages()` ne replace les figures que ~60 ms plus tard
  (`applyShapes` via MutationObserver) : lire le DOM tout de suite = faux négatif.
- 🔴 Ne jamais mettre de BACKTICKS dans un message de commit en double quotes :
  bash les exécute (`delete: command not found`) et le texte est amputé.

## Bancs
- `_v618/verify_v618_annoter_encadre.js` : **21/21** (outils 💬/🖍, panneau
  visible, note écrite sur le cadre, badge, badge sans déplacement, ancre
  préservée au clic, surlignage aux offsets exacts + couleur, bascule de
  retrait, note au re-rendu + export, refus sans ancre, 0 erreur JS).
- v609 **8/8**, v611 **52/52**, v617 **42/42**, smoke 127 modules, CRLF, sync 0 écart.

## Livraison VÉRIFIÉE SUR PIÈCE

# v620 — LE SURVOL D'UN CADRE SANS ANCRE (repli GÉOMÉTRIQUE)

## Constat (vidéo utilisateur)
Le commentaire s'affiche au survol quand le texte n'est PAS encadré, et **plus
rien** une fois le cadre posé — alors que le commentaire existe toujours.

## Cause
v619 cherchait par OFFSETS et **exigeait `f.ancre`**. Un cadre **dessiné à la
main** (ou inséré sans sélection) n'a AUCUNE ancre : la recherche renvoyait
vide -> aucune infobulle. La vidéo montre exactement cela : un grand cadre
magenta tracé autour d'une section, curseur à l'intérieur, rien.

## Correctif
- **Union** de deux méthodes : offsets (quand l'ancre existe) **ET** géométrie
  (le **CENTRE** du span `.atc-hl` doit tomber dans le rectangle du cadre).
- 🔴 Premier jet géométrique = **intersection de rectangles avec 4 px de
  tolérance** -> le **contrôle négatif du banc v619 l'a recalé** : un cadre posé
  sur « gamma » attrapait le commentaire de « beta », l'annotation VOISINE.
  Le test « centre dedans » est strict et suffisant.
- Union et non remplacement : une ancre PÉRIMÉE ne masque plus un commentaire
  visible.

## Pièges de banc (vérifiés)
- 🔴 **Offsets faux = surlignage FANTÔME** : `start:0,end:23` sur une phrase
  qui ne commence pas là -> le span disparaît au re-rendu, et le banc mesure
  ensuite une absence qui n'a rien à voir avec le correctif. Toujours calculer
  les offsets avec `content.indexOf(texte)`.
- 🔴 Après un re-rendu, `applyHighlights()` doit être rappelé AVANT de lire
  `.atc-hl` (le span n'est pas encore reposé).

## Bancs
- `_v620/verify_v620_survol_geometrie.js` : **9/9** (cadre sans ancre ->
  infobulle, contrôle négatif cadre déplacé loin, cadre ancré inchangé, note +
  commentaire ensemble, 0 erreur JS).
- v619 **11/11** (son contrôle négatif a attrapé le faux positif),
  v618 **21/21**, v609 **8/8**, v611 **52/52**, v617 **42/42**, smoke 127 modules.

# v621 — LE CADRE DEVIENT TRAVERSANT (sélection dans l'encadré)

## Demande
« Dans les encadrés, je veux pouvoir faire des surlignages et des commentaires
sur des mots/phrases sélectionnés — robuste, fluide, fonctionnel. »

## Cause
Le cadre est une SURCOUCHE qui capte la souris (pour être déplacé) : le texte
qu'il entoure n'était pas sélectionnable. Aucun surlignage ni commentaire
possible à l'intérieur. (Même racine que v618/v619/v620.)

## Correctif
- `pointer-events:none` sur `.atc-figbox` -> le texte redevient sélectionnable,
  la bulle d'annotation s'ouvre normalement.
- Saisie du cadre par des éléments dédiés `pointer-events:auto` : 4 BORDS
  (8 px), une POIGNÉE, les coins de redimension, la croix, le badge 💬.
- 🔴 **Les bords doivent être DANS la boîte ET la boîte DANS le contenu** :
  `.message-content{overflow:hidden}` rogne tout dépassement, et un élément
  rogné n'est PLUS hit-testé (cadre impossible à déplacer — mesuré). D'où :
  bords à `top:0` (et non -4 px) et position BORNÉE au contenu à la création
  (`insertFigureAt`) comme au ré-ancrage (`applyShapes`).
- Infobulle (v619/v620) reprise au `mousemove` sur **document** : la surface
  du cadre ne reçoit plus la souris. Réaction immédiate quand le cadre change
  (sinon un déplacement rapide n'affichait jamais rien), fermeture hors cadre,
  jamais pendant un glissement/sélection, jamais quand le pointeur est sur
  l'infobulle (sinon les boutons Copier/Supprimer étaient inutilisables).

## Défauts trouvés EN ÉCRIVANT LE BANC
- 🔴 Un simple CLIC sur un cadre retirait son **ancre texte** : `persistFig`
  comparait la géométrie du DOM à `f.x/f.y`, qui peuvent être PÉRIMÉS
  (ré-ancrage, borne au contenu) -> `aBouge` vrai pour 10 px d'écart alors que
  rien n'avait bougé. On compare maintenant au **début du geste** (ol/ot/ow/oh
  capturés au mousedown). Corollaire : `persistFig(f, fb, origine)`.
- 🔴 `insertFigureAt` posait le cadre à -8 px : hors de la zone visible, donc
  bords rognés et inutilisables. Borné.
- 🔴 Bancs : les surcouches de démarrage (`#auth-overlay` z 999999,
  `#setup-wizard-overlay` z 2000) couvrent l'app — un clic souris ne les
  traverse pas. Les neutraliser par CLASSE + `display:none !important` (un clic
  sur un bouton dépend de l'étape affichée).
- 🔴 Vérifier la hit-testabilité par `document.elementsFromPoint`, jamais par
  le style calculé : `pointer-events:auto` peut être correct et l'élément
  absent de la pile (rogné, ou recouvert).
